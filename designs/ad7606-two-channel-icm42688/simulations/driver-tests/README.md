# Native ADC driver and IMU timing checks

Run `python3 run.py` from this directory with a C11 compiler available (`CC` can select it). The ADC test includes the production `firmware/main/adc_ad7606.c` directly; it does not maintain a second copy. [Results and source hash](results.json) identify the tested source.

**Sixteen ADC groups pass for the current driver.** The ADC and eight timing-helper groups also pass repeated host execution with AddressSanitizer and UndefinedBehaviorSanitizer; these detect modeled memory/undefined-behavior faults, not electrical errors. They cover read-before-conversion rejection, 128-clock transfer configuration, signed channel order and disabled outputs, trigger timestamp retention, stuck/preexisting BUSY, unread conversions, late reads, SPI errors, restart, initialization error propagation, direct timer callback notification, BUSY assertion after CONVST, ignored CONVST, a disconnected/stuck-low BUSY line and the bounded BUSY wait. Tests inject the next conversion deadline during SPI and require failure rather than accepting the frame.

**Eight additional groups pass for the production `imu_timing.h` helper.** They cover first-anchor retention, per-sensor state, monotonic timestamp increments, counter rollover, observable gaps and rejection of duplicate/implausible deltas, backward read times, ambiguous long read intervals and arithmetic overflow. [Timing results and source hash](imu-timing-results.json).

This is host C execution with mocked peripheral APIs and synthetic counter observations. Critical-section macros are no-ops. There is no real scheduler, concurrent core, ESP-IDF peripheral implementation, electrical signal or timing measurement. These tests complement the [current integrated Wokwi recorder checks](../../docs/integrated-verification.html); they do not establish physical 8 kHz performance or calibrated synchronization.
