01 / Configuration

Choose one complete setup

Every package combines one ADC choice, one EMG capacity, and one IMU family. Use its breadboard plan, firmware, converter, PCB, and documentation together. Mixing packages can silently change GPIOs, bus protocols, timing records, and channel rules.

Current-parts path: if you have the RoboticsBD AD7606 module, two bare MyoWare 2.0 sensors, two GY-521 boards, and need exactly two EMG channels, use the fixed-two AD7606 / MPU-6050 package shown first.

02 / Architecture

One recorder, two acquisition paths

EMG and motion enter the ESP32-S3 through different hardware paths. The controller adds its timing evidence, writes the authoritative recording to microSD, and optionally forwards a best-effort copy over Wi-Fi.

MyoWare RAW2 default / 4 optional
→
Protected analogbias · buffer · filter
→
Simultaneous ADCAD7606 or ADS131M04
→
ESP32-S3counter · time · faults

Motion path

Foot and shank IMUs connect by SPI or shared I²C. ICM packets retain sensor timing; MPU packets retain FIFO order and ESP32 timing estimates.

Output path

microSD is the primary recording. Wi-Fi is a live convenience copy whose gaps remain visible rather than being hidden or filled.

Timing is evidence, not magic

ADC frames are simultaneous within the selected converter, but EMG and IMU clocks are independent. The recording preserves counters, trigger or data-ready timing, FIFO order, and read timing so alignment can be characterized later. Filtering and analog stages also introduce delay that must be measured before interpreting millisecond relationships.

Breadboard and compact PCB are electrically aligned at the functional level, but physically different. Development-board regulators, carrier pull-ups, wire length, connector parasitics, and layout noise mean a successful breadboard test does not prove the compact PCB's noise or radio performance.
03 / Laboratory build

Advance through ten measured gates

Build one block at a time. Later diagnostics preserve earlier stages, so a failure can be isolated without guessing across the complete system.

Power and midpoint

Verify polarity, regulated rails, startup, ripple, load response, and temperature with current limiting and dummy loads.

Controller

Verify programming, reset, buttons, LEDs, current, USB detection, and recording inhibition.

ADC and timing

Check communication or status, conversion timing, known DC codes, simultaneous frames, counters, and faults.

First EMG input

Use a synthetic source to measure offset, scaling, passband, baseline noise, clipping, and unplugged bias.

Remaining inputs

Verify identity, two/four-channel rules, disabled-channel handling, timing, and crosstalk.

Motion sensors

Add one IMU, then two. Verify identity, orientation, 200 Hz rate, stationary readings, timing evidence, and cable behavior.

microSD

Record continuously, convert data, test storage errors, fill behavior, and interrupted-file recovery.

Wi-Fi + SD

Observe explicit wireless gaps while confirming the primary SD file has no unexplained loss under radio load.

Battery system

Measure startup/shutdown, one-hour recording behavior, rail stability, temperature, and at least two hours of runtime.

MyoWare and wearable

Check mounting, motion artifact, cable security, AFO clearance, ethics, consent, and electrical safety before supervised recording.

Stop at a failed gate. Browsing a later stage is harmless; physically adding its hardware before the current stage passes makes fault isolation harder and invalidates the intended evidence chain.

04 / Firmware and data

Build and analyze the matching profile

Run commands from the selected design package. Expandable packages accept two or four EMG channels; fixed-two packages accept only two. Breadboard builds use GPIO47 for SD CMD, while compact-PCB builds use GPIO38.

Build a two-channel breadboard recorder

cd designs/<selected-configuration>/firmware
idf.py -B build-breadboard-2 \
  -DEMG_CHANNEL_COUNT=2 \
  -DAFO_HARDWARE=breadboard \
  -DAFO_WIFI=1 \
  -DAFO_DIAGNOSTIC_STAGE=0 \
  -DAFO_IMU_COUNT=2 build

Convert a recording

cd designs/<selected-configuration>
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r host/requirements.txt
python host/convert.py trial.afolog --out exported-trial

Receive the best-effort Wi-Fi copy

python host/live_receiver.py --help
# Join the recorder access point, start the receiver,
# then start recording on the device.

The converter exports timestamped EMG and IMU tables, metadata, quality findings, and basic plots. Recovery mode salvages valid records from an interrupted file and reports damage; it does not invent missing samples. Keep the original binary recording unchanged.

GitHub Pages hosts documentation only. A browser page on this public site cannot connect directly to a nearby ESP32 access point. Live reception runs on the laptop using the package's local receiver.

06 / Safety boundary

Keep bench power away from participants

Never attach a person during an instrument-connected electrical test. Disconnect charging, USB, the lab supply, oscilloscope grounds, and signal-generator grounds before electrodes are applied.

Human recording is a separate research activity. It requires institutional approval appropriate to the study, informed consent, exclusion and stop criteria, an electrical-safety review, a supervised procedure, and a plan for pseudonymous data handling.

The leg and AFO views illustrate placement only. They do not establish patient fit, pressure safety, comfort, biomechanics, or clinical benefit.
